# UI Specification — Extreme Sudoku

## 1. Назначение

Frontend предназначен для игры в классическое Sudoku 9×9 с упором на задачи высокой и экстремальной сложности.

Приложение должно:

- работать как статический сайт на GitHub Pages;
- не зависеть от Python во время работы пользователя;
- загружать готовые задачи из `data/puzzles.json`;
- одинаково хорошо работать на ПК, планшетах и смартфонах;
- иметь быстрый, чистый и современный интерфейс;
- не перегружать пользователя элементами управления;
- поддерживать решение сложных Sudoku с большим количеством заметок-кандидатов.

Frontend и генератор Sudoku должны быть независимыми.

---

# 2. Основная структура страницы

Основной экран состоит из:

1. верхней панели;
2. игрового поля Sudoku;
3. панели информации о текущей задаче;
4. панели ввода цифр;
5. панели действий;
6. дополнительной информации о задаче.

Пример логической структуры:

```text
┌───────────────────────────────────────┐
│ Extreme Sudoku              Settings │
├───────────────────────────────────────┤
│                                       │
│              9×9 GRID                 │
│                                       │
├───────────────────────────────────────┤
│ Extreme · 18 clues · 00:14:32         │
├───────────────────────────────────────┤
│  1  2  3  4  5  6  7  8  9           │
├───────────────────────────────────────┤
│ Undo  Erase  Notes  Hint  Restart     │
└───────────────────────────────────────┘
```

На широком экране часть элементов может располагаться справа от поля.

---

# 3. Игровое поле

Поле:

```text
9 × 9
```

содержит 81 клетку.

Каждые 3×3 клетки визуально объединяются в блок.

Границы блоков 3×3 должны быть заметно толще обычных линий между клетками.

Поле должно сохранять квадратную форму при любом размере окна.

---

# 4. Виды содержимого клетки

Клетка может находиться в одном из состояний:

```text
given
user-value
empty
notes
selected
related
same-value
error
hint
```

## 4.1 Given

Исходная цифра задачи.

Требования:

- пользователь не может её изменить;
- визуально отличается от введённых пользователем цифр;
- должна хорошо читаться;
- не должна выглядеть как disabled-элемент.

---

## 4.2 User value

Цифра, введённая пользователем.

Она должна визуально отличаться от исходной цифры.

---

## 4.3 Notes

Кандидаты располагаются внутри клетки сеткой:

```text
1 2 3
4 5 6
7 8 9
```

Каждая заметка должна оставаться читаемой даже на мобильном устройстве.

---

# 5. Выбор клетки

При клике или касании клетка становится активной.

Необходимо подсветить:

- выбранную клетку;
- её строку;
- её столбец;
- её блок 3×3.

Если выбранная клетка содержит цифру, дополнительно подсветить остальные клетки с этой цифрой.

Пример:

```text
выбрано r5c4 = 7

→ подсвечивается row 5
→ column 4
→ box
→ все остальные 7
```

Подсветки должны различаться по интенсивности.

---

# 6. Ввод цифр

Ввод должен работать:

- кнопками интерфейса;
- клавиатурой ПК;
- цифровыми клавишами;
- NumPad.

Допустимые клавиши:

```text
1–9       ввод цифры
Backspace удалить
Delete    удалить
0         удалить
N         Notes
Ctrl+Z    Undo
```

Стрелки:

```text
↑
↓
←
→
```

перемещают выделенную клетку.

---

# 7. Панель цифр

На экране должна присутствовать панель:

```text
1 2 3 4 5 6 7 8 9
```

После завершения всех девяти экземпляров определённой цифры допускается визуально приглушать соответствующую кнопку.

Например, если все девять цифр `7` уже правильно расположены:

```text
7 → disabled / muted
```

---

# 8. Notes Mode

Кнопка:

```text
Notes
```

переключает режим:

```text
NORMAL
NOTES
```

В режиме Notes введённая цифра становится маленьким кандидатом.

Необходимо явно показывать пользователю, что Notes Mode активирован.

Например:

```text
Notes ●
```

---

# 9. Автоматическое удаление кандидатов

Настройка:

```text
Auto-remove notes
```

По умолчанию:

```text
ON
```

Если пользователь ставит окончательное значение `5`, заметка `5` автоматически удаляется из:

- той же строки;
- того же столбца;
- того же блока 3×3.

---

# 10. Undo

Поддерживать историю действий.

Undo должен восстанавливать:

- введённые значения;
- удалённые значения;
- notes;
- автоматически удалённые notes.

Одна операция пользователя должна считаться одной undo-группой.

---

# 11. Erase

Кнопка:

```text
Erase
```

удаляет:

- пользовательское значение;
- либо notes из выбранной клетки.

Исходные clues удалять нельзя.

---

# 12. Restart

`Restart` возвращает задачу в исходное состояние.

Перед сбросом прогресса необходимо подтверждение:

```text
Restart this puzzle?
```

---

# 13. New Game

Кнопка:

```text
New Game
```

позволяет выбрать уровень сложности.

Уровни:

```text
Easy
Medium
Hard
Expert
Extreme
Ultra Extreme
```

В первоначальной версии основной фокус:

```text
Extreme
Ultra Extreme
```

---

# 14. Hint

Кнопка:

```text
Hint
```

не должна просто автоматически вставлять случайную цифру.

Для сложных Sudoku желательно поддерживать два уровня помощи.

## Level 1

Показать:

```text
какую технику сейчас можно применить
```

Например:

```text
Technique: X-Wing
```

## Level 2

Показать:

- клетки;
- кандидатов;
- краткое объяснение логики.

Пример:

```text
X-Wing on digit 7 in rows 2 and 8.
Candidate 7 can be removed from r5c3.
```

Если данные о solution path отсутствуют, допускается базовый Hint:

```text
Reveal one correct cell
```

Но архитектура должна позволять позже подключить логические подсказки от Human Solver.

---

# 15. Timer

Таймер начинает отсчёт после начала игры.

Формат:

```text
MM:SS
```

или после часа:

```text
HH:MM:SS
```

Необходимо поддерживать:

```text
pause
resume
```

При сворачивании вкладки таймер должен рассчитываться по реальному времени, а не зависеть от частоты вызова JavaScript timer.

---

# 16. Ошибки

Должен существовать счётчик:

```text
Mistakes: 0
```

Режим проверки ошибок должен быть настраиваемым.

Варианты:

```text
Immediate
On completion
Off
```

### Immediate

При неправильной цифре клетка сразу помечается как ошибка.

### On completion

Ошибка показывается только при проверке результата.

### Off

Пользователь решает Sudoku без автоматической проверки.

Для Extreme/Ultra Extreme желательно позволить полностью отключить автоматическую проверку.

---

# 17. Завершение Sudoku

После правильного заполнения всех клеток показать итоговый экран:

```text
Solved!

Difficulty: Ultra Extreme
Time: 01:42:17
Mistakes: 2
Hints: 0
Clues: 18
```

Дополнительно:

```text
New Puzzle
Restart
Puzzle Info
```

---

# 18. Информация о задаче

Показывать минимум:

```text
Difficulty
Clues
```

При наличии данных:

```text
Rating
ID
Hardest technique
Advanced techniques
```

Пример:

```text
Ultra Extreme
18 clues
Rating: 9.4

Hardest:
Forcing Chain
```

---

# 19. Puzzle Details

Отдельная панель или modal:

```text
Puzzle Details
```

может показывать:

```text
ID: EXT-000128
Clues: 18
Difficulty: Ultra Extreme
Rating: 9.4

Techniques:
X-Wing ×1
XY-Wing ×2
AIC ×3
ALS-XZ ×1
Forcing Chain ×1

Bottlenecks: 4
Longest chain: 17
```

Эта информация необязательна для обычной игры, поэтому не должна перегружать основной экран.

---

# 20. Mobile layout

Для смартфонов интерфейс должен помещаться по ширине экрана без горизонтального скролла.

Приоритет:

```text
Sudoku Grid
Numbers
Main Actions
Game Info
```

Пример:

```text
Extreme Sudoku

┌───────────────┐
│               │
│   9 × 9 GRID  │
│               │
└───────────────┘

Extreme · 18 clues
00:23:18

1 2 3 4 5
6 7 8 9

Undo   Erase
Notes  Hint
```

Поле должно занимать максимально возможную ширину.

---

# 21. Desktop layout

На широком экране рекомендуется:

```text
┌─────────────────────────────┐
│                             │
│         Sudoku Grid         │   Info
│                             │   Timer
│                             │   Difficulty
│                             │   Actions
│                             │   Numbers
└─────────────────────────────┘
```

Не следует растягивать Sudoku на весь экран.

Рекомендуемый максимальный размер игрового поля:

```text
500–650 px
```

в зависимости от дизайна.

---

# 22. Responsive breakpoints

Не привязывать логику строго к конкретным устройствам.

Ориентировочно:

```text
< 600 px     mobile
600–900 px   tablet
> 900 px     desktop
```

---

# 23. Visual style

Стиль:

- минималистичный;
- современный;
- без визуального шума;
- главный акцент — Sudoku grid;
- крупная типографика;
- достаточный whitespace;
- отсутствие ненужных декоративных элементов.

Не использовать стилистику:

```text
старых Flash-игр
казино
мобильных игр с большим количеством баннеров
```

---

# 24. Themes

Предусмотреть:

```text
Light
Dark
System
```

По умолчанию:

```text
System
```

Выбор пользователя сохранять в localStorage.

---

# 25. Цветовая система

Не привязывать бизнес-логику к конкретным HEX-цветам.

Использовать CSS variables:

```css
--background
--surface
--text-primary
--text-secondary

--grid-line
--grid-line-strong

--cell-selected
--cell-related
--cell-same-number

--given-number
--user-number
--note-number

--error
--success
--accent
```

---

# 26. Accessibility

Обязательно:

- достаточный contrast;
- управление клавиатурой;
- заметный focus state;
- кнопки должны иметь `aria-label`;
- клетки должны иметь понятные accessibility labels.

Пример:

```text
Row 4, column 7, empty
```

или:

```text
Row 4, column 7, given 9
```

---

# 27. Touch support

Минимальный размер кликабельных кнопок:

```text
≈ 44 × 44 px
```

Не полагаться только на hover.

Все основные функции должны работать на touchscreen.

---

# 28. Local storage

Сохранять локально:

```text
current puzzle ID
current board
notes
timer start / elapsed time
mistake count
settings
theme
```

После перезагрузки страницы пользователь должен продолжить текущую игру.

---

# 29. Save format

Frontend должен сохранять прогресс отдельно от исходного puzzle.

Пример:

```json
{
  "puzzleId": "extreme-000128",
  "values": "...",
  "notes": {},
  "elapsedSeconds": 2418,
  "mistakes": 1
}
```

---

# 30. Data loading

Frontend должен загружать:

```text
data/puzzles.json
```

В коде не должно быть жёстко прописанных Sudoku.

Допускается одна встроенная fallback-задача только для режима разработки.

---

# 31. Puzzle selection

При нажатии `New Game`:

1. выбрать difficulty;
2. получить список подходящих puzzles;
3. выбрать задачу;
4. по возможности не повторять недавно сыгранные задачи.

ID ранее решённых задач можно хранить в localStorage.

---

# 32. Loading state

При загрузке базы отображать:

```text
Loading puzzles...
```

Если база недоступна:

```text
Unable to load puzzle database.
```

Интерфейс не должен зависать или выдавать необработанную JS-ошибку.

---

# 33. Invalid puzzle handling

Если задача имеет неправильный формат:

```text
не 81 клетка
неизвестные символы
неизвестный difficulty
```

frontend должен пропустить её и записать warning в console.

Одна повреждённая задача не должна ломать всю базу.

---

Минимальное состояние игры:

```text

```

---

# 37. Что frontend НЕ должен делать

Frontend не должен:

- генерировать Extreme Sudoku;
- определять уникальность Sudoku;
- выполнять тяжёлый Human Solver;
- рассчитывать финальный рейтинг сложности;
- запускать эволюционный алгоритм.

Эти задачи выполняет Python generator.

Frontend получает уже проверенные задачи.

# 40. Основной принцип UI

Пользователь должен открыть страницу и сразу понять:

```text
это Sudoku
```

без обучения интерфейсу.

Главным визуальным объектом всегда остаётся игровое поле.

Всё остальное должно помогать решению задачи, а не конкурировать с ним за внимание.
